Pasul 1 – Selectori și cascadă

Acesta este un paragraf cu clasa „important”.

p.important {          /* specificitate (0,1,1) */
    color: #c0392b;
}

.important {           /* specificitate (0,1,0) */
    color: var(--primary);
    font-size: 1.25rem;
    padding: 0.75rem 1rem;
}

Care declarație câștigă?

Ambele reguli setează color. Câștigă p.important, deci textul este roșu, deși regula .important apare mai jos în fișier.

Specificitatea se scrie ca (ID-uri, clase/atribute/pseudo-clase, elemente):

SelectorID-uriClaseElementeSpecificitate
p.important011(0,1,1)
.important010(0,1,0)

Valorile se compară de la stânga la dreapta: ID-urile sunt egale (0 = 0), clasele sunt egale (1 = 1), iar la elemente 1 > 0. Așadar (0,1,1) > (0,1,0) și câștigă p.important. Celelalte proprietăți (font-size, padding) sunt declarate doar în .important, deci se aplică fără conflict.

La egalitate de specificitate câștigă ordinea în fișier

Acest paragraf are clasa „nota” și este verde.

.nota { color: var(--primary); }   /* (0,1,0) – pierde */
.nota { color: #1e8449; }          /* (0,1,0) – câștigă, este ultima */

Ambele reguli au specificitatea (0,1,0), așa că se aplică regula declarată ultima în fișier.

Verificarea în DevTools

  1. Click dreapta pe paragraful roșu → Inspect (sau F12).
  2. În tab-ul Styles apar ambele reguli, ordonate după prioritate: p.important deasupra, .important dedesubt.
  3. Declarația color: var(--primary) din .important apare tăiată, adică a fost suprascrisă. font-size și padding nu sunt tăiate.
  4. În tab-ul Computed, la color, se vede valoarea finală, rgb(192, 57, 43), și regula din care provine.

Pasul 2 – Box Model

.card-a – box-sizing: content-box
.card-b – box-sizing: border-box
.card-a, .card-b {
    width: 300px;
    padding: 20px;
    border: 5px solid;
}
.card-a { box-sizing: content-box; }
.card-b { box-sizing: border-box; }

Calculul lățimii totale

.card-a (content-box): width se aplică doar conținutului, iar padding-ul și border-ul se adaugă pe deasupra:

300 + 2·20 + 2·5 = 300 + 40 + 10 = 350px

.card-b (border-box): width include padding-ul și border-ul, deci lățimea totală rămâne 300px. Pentru conținut rămâne 300 − 2·20 − 2·5 = 250px.

Ce arată diagrama Box Model din DevTools

Selectează cardul în Elements și deschide tab-ul Computed. Diagrama are, din interior spre exterior, content → padding → border → margin.

content (lățime)paddingborderLățime totală
.card-a30020 pe fiecare parte5 pe fiecare parte350px
.card-b25020 pe fiecare parte5 pe fiecare parte300px

La hover pe element, DevTools afișează și dimensiunea totală: 350 × … pentru .card-a și 300 × … pentru .card-b.

.flex-nav {
    display: flex;
    flex-wrap: wrap;                  /* pe ecrane înguste linkurile trec pe rândul următor */
    justify-content: space-between;   /* brandul în stânga, linkurile în dreapta */
    align-items: center;              /* centrate pe verticală */
    gap: 1rem;
}

justify-content: space-between pune primul element (brandul) la marginea din stânga și ultimul (lista de linkuri) la marginea din dreapta. Cu flex-wrap: wrap, dacă ecranul e prea îngust, lista trece pe rândul următor în loc să iasă din lățime.

Grid

Layout pe rânduri și coloane.

Responsive

Pagini care se adaptează la orice ecran.

.gallery {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(min(100%, 240px), 1fr));
    gap: 16px;
    max-width: 960px;
}

Cum funcționează

  • auto-fit pune atâtea coloane câte încap, fiecare de minim 240px, iar 1fr le întinde egal pe spațiul rămas.
  • min(100%, 240px): pe un ecran mai îngust de 240px minimul devine 100% din lățime, deci cardul nu iese din pagină.

De ce max-width: 960px?

Fără limită, pe un ecran lat ar încăpea 4 sau mai multe coloane. Calculăm lățimea de care e nevoie (coloane + spații dintre ele):

  • 3 coloane: 3·240 + 2·16 = 752px
  • 4 coloane: 4·240 + 3·16 = 1008px

Cu max-width: 960px avem 752 ≤ 960 < 1008: încap 3 coloane, dar niciodată 4. Deci galeria are maxim 3 coloane, iar pe ecrane mai înguste trece automat la 2 sau 1.

Conținut

Pe mobil sidebar-ul și conținutul sunt unul sub altul, pe o singură coloană. De la 768px în sus devin două coloane, iar conținutul este de două ori mai lat decât sidebar-ul (1fr 2fr).

.layout {
    display: grid;
    grid-template-columns: 1fr;          /* mobile-first: o coloană */
    gap: 1rem;
}

@media (min-width: 768px) {
    .layout {
        grid-template-columns: 1fr 2fr;  /* tabletă/desktop: două coloane */
    }
}

Cerințe de accesibilitate și responsive

  • Meta viewport: <meta name="viewport" content="width=device-width, initial-scale=1.0"> face ca pe telefon pagina să folosească lățimea reală a ecranului.
  • Fără scroll orizontal: grilele folosesc fr și min(100%, …), nav-ul are flex-wrap, iar blocurile de cod, tabelele și demo-ul de la Pasul 2 (350px) au overflow-x: auto, deci derulează doar ele, nu toată pagina.
  • Focus vizibil: :focus-visible { outline: 3px solid var(--accent); }. Apasă Tab și fiecare link primește un contur turcoaz.
  • Zoom 200%: textul folosește rem și nu există înălțimi fixe, așa că la zoom conținutul crește, iar layout-ul trece pe o coloană (la zoom 200% lățimea efectivă scade sub 768px).
